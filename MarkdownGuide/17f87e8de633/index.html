Markdown食用指北（二） | 段落、列表与引用

发表于2025-12-15|MarkdownGuide
|总字数:3k|阅读时长:9分钟|浏览量:

第一章解决了“每一种语法怎么写”，这一章解决“多种内容怎样稳定地组合在一起”。很多 Markdown 排版问题并不是符号记错，而是空行、缩进和块级结构之间的关系没有处理好。

本章完成后，你应该能够写出包含多级列表、任务清单、长引用、列表内代码和多段说明的文档，并能通过观察源码快速找到结构错误。

1. 先理解块级元素与行内元素

Markdown 内容大致可以分为两类。

1.1 块级元素

块级元素通常独占一块区域，并通过换行、空行或缩进确定边界：

  • 标题
  • 段落
  • 列表
  • 引用
  • 代码块
  • 表格
  • 分隔线

例如，下面有一个段落和一个列表：

1.2 行内元素

行内元素出现在段落、标题、列表项或引用内部：

  • 强调与加粗
  • 行内代码
  • 链接
  • 图片
  • 删除线

理解这一区别后，许多组合规则就会变得自然：块级元素决定大结构，行内元素修饰结构中的文字。

2. 空行是最重要的结构符号

Markdown 没有“段落结束”按钮，空行承担了这个作用。

2.1 一个空行通常就够了

连续两个、三个甚至更多空行，渲染后通常不会产生更大的间距。页面间距由 CSS 决定，不要依靠堆积空行控制版式。

2.2 哪些位置建议留空行

为了兼容更多解析器，推荐在以下结构前后留一个空行：

  • 标题
  • 列表
  • 引用
  • 围栏代码块
  • 表格
  • 分隔线

子列表需要相对父列表缩进。常见做法是使用两个或四个空格；为了避免不同解析器的差异，本系列推荐四个空格。

超过三级的嵌套通常很难阅读。遇到过深结构时，优先考虑：

  • 拆成多个小节。
  • 把子项改成普通段落。
  • 使用表格表达属性对照。
  • 将复杂流程拆成多个步骤。

Markdown 能写出深层列表，不代表深层列表适合读者。

12. 缩进、Tab 与不可见字符

12.1 优先使用空格

Tab 在不同编辑器中可能显示为二、四或八个空格。Markdown 解析器对 Tab 的展开方式也可能不同，因此嵌套结构优先使用普通空格。

12.2 行尾空格很难观察

硬换行依赖两个行尾空格，但许多编辑器会自动删除行尾空格。团队文档中如果频繁需要硬换行，可以：

  • 使用明确的段落。
  • 在目标平台允许时使用 <br>。
  • 配置编辑器保留必要的行尾空格。

14. 排错顺序

组合结构渲染异常时，按下面的顺序检查：

  1. 检查代码围栏是否闭合。
  2. 检查列表、引用标记后是否有空格。
  3. 检查嵌套内容的缩进是否一致。
  4. 检查块级元素前后是否缺少空行。
  5. 检查是否混入全角符号或 Tab。
  6. 把复杂内容逐段删除，找到最先出错的位置。
  7. 在目标网站而不仅是本地编辑器中预览。

Markdown 错误经常会向后影响很多行。看到后半篇全部错位时，问题通常发生在更早的位置。

15. 本章小结

稳定组合 Markdown 结构的核心只有几条：

  • 用空行划分块级内容。
  • 用一致缩进表达从属关系。
  • 用有序列表表达步骤，用无序列表表达并列项。
  • 复杂列表项中的段落、引用和代码要缩进。
  • 任务列表属于常见扩展，发布前要预览。
  • 遇到大面积错位时，先检查更早出现的围栏和缩进。

下一章将集中处理链接、图片、路径、锚点和表格。这些内容最容易出现“本地正常、发布后失效”的问题。
