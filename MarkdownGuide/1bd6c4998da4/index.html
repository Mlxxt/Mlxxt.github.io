Markdown食用指北（六） | 长文结构、目录与导航

发表于2026-01-05|MarkdownGuide
|总字数:3.9k|阅读时长:11分钟|浏览量:

会写 Markdown 语法，不等于会写一篇好维护的长文。博客文章还涉及元数据、标题层级、自动目录、锚点、系列导航、资源路径和发布流程。本章专门处理这些“语法之外、但直接决定阅读体验”的问题。

1. Front Matter 是什么

许多静态博客会在 Markdown 文件开头读取一段元数据，常见形式是 YAML Front Matter：

它位于文件最前面，由两条 --- 包围。Front Matter 不是 Markdown 核心语法，而是站点生成器在渲染正文前读取的配置。

1.1 常见字段

字段 常见用途
title 文章标题
date 发布时间
updated 更新时间
tags 标签
categories 分类
description 摘要或搜索描述
cover 封面图片
draft 是否为草稿
toc 是否显示目录

字段名称和含义由博客系统与主题决定。不要因为其他网站使用了某个字段，就直接假设当前网站也支持。

1.2 Front Matter 不是正文

Front Matter 中的 title 通常由主题渲染成文章大标题。正文再写一个完全相同的一级标题，可能造成：

  • 页面出现两个标题。
  • 标题层级重复。
  • 自动目录多出一项。
  • 搜索和无障碍结构不理想。

如果主题已经负责文章标题，正文从二级标题开始是常见且合理的做法。

7. 控制目录长度

目录太短无法导航，太长又会淹没读者。

7.1 二级标题负责主要路线

读者只看二级标题时，应该能够理解文章从哪里开始、经过什么、在哪里结束。

7.2 三级标题只拆分真正独立的主题

适合三级标题：

  • 不同操作系统。
  • 不同安装方式。
  • 一个大主题下的多个独立概念。
  • 读者可能需要直接跳转到的内容。

不适合三级标题：

  • 只有一句话的提醒。
  • 每个列表项。
  • “示例”“说明”“注意”反复出现。
  • 只为了增加视觉间距。

7.3 四级标题谨慎使用

如果网站目录只收集一到三级标题，四级标题虽然不进入目录，但仍然属于文章结构。不要把它当成“隐藏目录的粗体”滥用。

本系列优先使用粗体短语表达更小的局部层次，从而保持目录简洁。

9. 标题锚点的稳定性

目录和页内链接通常依赖标题生成的 id。标题发布后改名，可能导致旧锚点失效。

提高稳定性的做法：

  1. 发布前确定标题用词。
  2. 标题少用特殊符号。
  3. 不在标题里放图片。
  4. 少在标题里放行内代码或链接。
  5. 避免重复标题。
  6. 修改公开标题后检查站内链接。

自动锚点规则属于解析器行为，中文、标点和大小写的处理并不完全统一。

10. 先写大纲，再写正文

长文直接从第一段开始写，很容易后半段重复或失去方向。

10.1 先写问题清单

在动笔前回答：

  • 目标读者是谁？
  • 读者开始前已经知道什么？
  • 学完后应该能做什么？
  • 哪些概念必须先解释？
  • 哪些步骤存在风险？
  • 如何验证读者成功完成？

10.2 再写标题骨架

确认顺序合理后再填内容。标题骨架也能提前暴露目录是否过长。

11. 每一章都要有学习闭环

一篇入门教程至少包含：

  1. 目标：读者会学到什么。
  2. 解释：概念为什么存在。
  3. 示例：源码和渲染或运行结果。
  4. 练习：读者亲手完成任务。
  5. 验证：如何判断完成正确。
  6. 排错：常见失败表现。
  7. 总结：把知识压缩成可复习的要点。

只罗列语法是一份速查表，不是完整教程。只有解释没有练习，也很难形成稳定记忆。

12. 系列文章导航

多篇教程应该让读者知道自己位于系列中的什么位置。

常见导航内容：

  • 上一章。
  • 当前章。
  • 下一章。
  • 完整系列目录。

使用相对链接：

如果文件会被站点生成器转换成不同 URL，需要确认源码 .md 链接是否会被自动转换。不同系统处理不同。

12.1 导航放在开头还是结尾

  • 开头导航方便连续阅读和快速定位。
  • 结尾导航方便学完后继续。
  • 两处都放会增加维护成本。

本系列选择在结尾放置导航，更具美观（原因其实是网站主题提供了代码便利）

14. 图片与资源目录

常见组织方式有两种。

14.1 全站公共资源

优点是集中管理，缺点是文章迁移时需要同时寻找资源。

14.2 文章资源同目录

优点是归属清楚，但是否支持取决于站点生成器。

无论使用哪种方式，都应遵循项目现有约定，不要自行混合出第三套资源规则。

15. 摘要与阅读全文

博客首页通常显示文章摘要。摘要可能来自：

  • Front Matter 的 description。
  • 正文第一段。
  • 站点专用的摘要分隔标记。
  • 自动截取固定字数。

有些系统使用：

它不是通用 Markdown。使用前应确认当前站点的生成器与主题规则。

好的摘要应该说明：

  • 文章解决什么问题。
  • 适合谁。
  • 读者能获得什么。

不要让摘要只剩“大家好，今天来写一篇文章”。

16. 外链、内链与系列关系

合理的链接能形成知识网络。

16.1 内链

链接到站内相关章节：

  • 减少重复解释。
  • 帮助读者补基础。
  • 让搜索引擎理解文章关系。

链接文字应写主题，不写“这里”。

16.2 外链

外部资料优先链接：

  • 官方规范。
  • 官方文档。
  • 原始研究或项目仓库。
  • 长期稳定的权威来源。

外链可能失效，因此正文仍应包含完成当前任务所需的关键解释，不能只写“详见链接”。

16.3 链接维护

定期检查：

  • 相对路径是否因文件移动失效。
  • 外链是否重定向或下线。
  • 页内锚点是否因标题修改失效。
  • 链接文字是否仍与目标一致。

17. 写作风格的一致性

系列教程应提前约定：

项目 建议
无序列表 统一使用 -
强调 统一使用 **粗体**
代码语言 使用常见小写标识
文件路径 使用行内代码
菜单项 使用粗体
按键 使用行内代码或统一的 kbd
提示 块引用加粗体标签
标题 主要章节二级，子主题三级

一致性减少读者理解格式的成本，也让后续维护更快。

18. 可访问性与移动端

发布前不仅要看桌面大屏。

18.1 图片

  • 写有效替代文字。
  • 截图中的关键文字在正文重复说明。
  • 不使用颜色作为唯一信息。
  • 图片宽度不要撑破页面。

18.2 链接

  • 链接文字说明目标。
  • 不依赖“鼠标悬停”传递关键信息。
  • 避免连续多个都叫“查看详情”的链接。

18.3 表格和代码

  • 超宽表格在手机上可能难以使用。
  • 长代码块需要横向滚动。
  • 能用列表表达时，不必强行使用大表格。
  • 重要结果在代码块后用文字总结。

18.4 标题

连续且清楚的标题层级能帮助键盘用户和屏幕阅读器快速导航。

19. 发布前检查流程

19.1 内容检查

  • 目标读者和前置知识是否明确。
  • 每个步骤是否说明目的。
  • 示例是否完整且准确。
  • 是否有验证方法。
  • 是否解释常见错误。
  • 结论是否与正文一致。

19.2 Markdown 结构检查

  • Front Matter 是否闭合。
  • 标题层级是否连续。
  • 代码围栏是否闭合。
  • 列表缩进是否一致。
  • 链接和图片括号是否配对。
  • 表格列数是否一致。
  • 示例标题是否位于代码块中。

19.3 网站效果检查

  • 自动目录是否只包含真实章节。
  • 页内跳转是否正确。
  • 移动端是否可读。
  • 深色模式下代码和图片是否清晰。
  • 图片是否成功加载。
  • 公式、图表和提示框是否正确渲染。

19.4 安全与隐私检查

  • 没有密码、令牌、Cookie 和私钥。
  • 没有个人路径、内网域名和服务器地址。
  • 截图没有个人通知和账户信息。
  • 示例数据不是真实用户数据。
  • 外部图片和引用内容拥有合理使用权限。

20. 更新已经发布的文章

文章发布后仍会变化。更新时：

  1. 保留稳定标题，避免破坏锚点。
  2. 记录真正影响读者的版本变化。
  3. 检查旧截图是否与当前界面冲突。
  4. 重新运行教程中的命令。
  5. 重新检查链接。
  6. 更新日期字段时遵循站点规则。
  7. 不把旧内容全部用删除线保留在正文。

21. 本章小结

  • Front Matter 是博客元数据，不属于 Markdown 核心语法。
  • 主题已经生成文章标题时，正文通常从二级标题开始。
  • 二级标题表示主要章节，三级标题表示可独立导航的子主题。
  • 不进入目录的小层次优先使用粗体引导句，而不是滥用四级标题。
  • 示例标题放进代码块，避免污染自动目录。
  • 长文应包含目标、解释、示例、练习、验证、排错和总结。
  • 文件名、标题锚点和资源路径发布后都应尽量保持稳定。
  • 最终效果必须在真实博客、移动端和主题样式中检查。
