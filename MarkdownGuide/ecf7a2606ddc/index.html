Markdown食用指北（四） | 代码与技术文档

发表于2025-12-24|MarkdownGuide
|总字数:2.9k|阅读时长:9分钟|浏览量:

Markdown 在程序员和技术写作者中流行，一个重要原因是它能让“解释文字”和“代码内容”同时保持清楚。本章不只介绍如何把代码框起来，还会讨论命令、输出、配置、差异片段和长代码示例应该怎样组织。

1. 行内代码的用途

一对反引号用于标记段落中的短代码：

适合使用行内代码的内容包括：

  • 命令，例如 npm run build。
  • 文件和目录，例如 src/index.js。
  • 变量、函数和类型，例如 userName、render()、Promise。
  • 配置键和值，例如 NODE_ENV=production。
  • 键盘输入或字面文本，例如输入 yes。

不要把普通产品名、英文术语或整段强调内容都写成代码。行内代码表达的是“按字面读取的技术内容”，不是另一种粗体。

13. 代码块中的长行

长 URL、命令或压缩代码会迫使页面横向滚动。处理方式：

  • 在语言允许的位置合理换行。
  • 将长参数拆成多行。
  • 用变量保存重复路径。
  • 不在教程中展示压缩后的代码。
  • 不为了视觉换行而破坏可复制性。

代码块是否自动换行由网站 CSS 决定。技术代码通常适合横向滚动，因为视觉换行可能让缩进和行号难以对应。

18. 技术示例的安全边界

发布命令和配置前检查：

  • 不包含真实密码、令牌和私钥。
  • 不包含内网地址、服务器名称和个人目录。
  • 不包含用户真实数据。
  • 危险命令明确说明影响范围。
  • 删除、覆盖、部署等操作提供前置提醒。
  • 示例域名使用 example.com 等保留用途地址。
  • 示例密钥使用明显无效的占位内容。

截图中的终端提示符也可能暴露用户名、主机名和工作路径。

19. 代码类内容排错清单

  1. 行内反引号是否成对。
  2. 围栏代码块是否闭合。
  3. 外层围栏是否长于示例中的内层围栏。
  4. 语言标识是否准确。
  5. 命令与输出是否明确分开。
  6. Shell 环境是否写清楚。
  7. 代码是否能够复制，还是混入了提示符和教学箭头。
  8. 省略内容是否明确标注。
  9. 示例文件名和执行目录是否说明。
  10. 敏感信息是否清理。

20. 本章小结

  • 行内代码用于命令、文件名、标识符和字面值。
  • 围栏代码块适合多行代码，并可附加语言标识。
  • 教程嵌套代码围栏时，外层围栏要更长。
  • 命令、输出、配置文件和 Diff 应明确区分。
  • 技术示例要交代文件、位置、目的、验证和常见错误。
  • Mermaid、高亮和按键样式属于平台能力，不应假设处处可用。
  • 可复制性、准确性和安全性比花哨的高亮更重要。

下一章将进入 Markdown 扩展语法，讨论脚注、提示框、折叠内容、数学公式、HTML 和其他平台特性。
